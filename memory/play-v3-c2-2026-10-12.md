## The one rule everything hangs on: one submission path

An arrow, a menu pick and a drawn block submit what the list would because they ARE the list:
`dock.beginExternal(option)` starts `PromptPanel`'s own chain, and the mounted picker is driven
through its own DOM. Nothing under `lib/v3/` builds `targets` / `blockers` or calls `act` — the
single `act(` is `TableV3`'s pass-through. The picker therefore stays in sync and stays the fallback
(criterion 1's second half). Held by the gate below and by the probes' POST-body comparisons.

## `stores.js` (additive)

`startPassUntil(mode)` also takes `{ kind, predicate }`; only the predicate lookup differs. The loop,
every unconditional stop (cancelled, game over, no decision, a non-`Priority` decision, no pass
offered, failed request, 400-pass guard), the concurrency guard and the `passUntil` shape are shared.
String modes (`'my-turn'`, `'phase-end'`) go through the same table and the same failure branch as before.

## Review (`/review`, Opus) — 1 HIGH, 1 MEDIUM fixed in-cycle

1. **HIGH, fixed** — the auto-pass panel could start a run while a picker chain was open; the picker
   stayed mounted on the old option and its Confirm posted a stale action index against a later
   decision (reviewer saw a 400; a wrong cast was not constructed but not excluded). `AutoPass` is
   now inert while `targeting.chainOpen`, as `PromptPanel`'s own pass buttons are. Three probe checks
   added (modes disabled with the reason; a forced press sends nothing and the picker keeps its
   decision; Back re-enables). Not exercised: `.resume` disabled under an open picker (no scenario has
   a paused run and a targeted action at the same point); it shares the `canStart` guard.
2. **MEDIUM, fixed (probe) / logged (limit)** — no check that a new game does not inherit the order.
   Added: a deal from the table's menu mints a new key and shows seat-view order. Still true and
   documented in `order.js`: the summary has no game id, so a game re-dealt through the bare API (or
   another tab) to a point at or past the stored counters keeps the key, and early object ids repeat
   across deals. Cosmetic; the fix is `GameSummary.game_id` (C3).
3. LOW, fixed — Escape during a blocker drag closed the whole block stage; it now cancels the drag only.
4. LOW, fixed — the gate did not see `act` reached through another import; it now refuses `api.js`
   and an `act` import from `stores.js` outside `TableV3`, and its doc says what a source gate cannot see.
5. LOW, fixed — the "confirm when complete" intent of an arrow outlived its gesture; it now expires two flushes later.
6. LOW, fixed in the probe — source-menu check was a subset; scenario drift did not affect the exit code.

## Decisions and departures

- **No game id exists** (`GameSummary` deliberately carries no seed either), so "keyed by game id" is
  a client key in `localStorage` (`v3-game`), kept while the summary's counters are consistent with
  the same table and re-minted by this client's own deal / mulligan. See Review 2.
- **Arrows are amber, not red.** Red solid already means "targeted by something on the stack"
  (`.card.targeted`); the could-choose outline is dashed amber, the chosen target red.
- **A table click toggles and never confirms**; only a drop and "Target with" confirm, and only when
  the picker's filled count equals its max.
- **Auto-pass never passes without a gesture.** Choosing a mode starts a run; a stop condition or a
  real (non-`Priority`) decision PAUSES it with a Resume button; reaching the "until" point returns
  to Off; a reload never restarts. Eleven steps are offered (Untap and Cleanup give no priority).
  The step select is always visible (the mode click starts the run, so the step is chosen first).
- **`targeted` red outline not set** (brief's instruction): `StackItemView.targets` is rendered text,
  no object ids; matching names would be inference (Invariant 7). C3, with a `target_ids` field.
- **Blocker box sits above the list** and widens the centred float (`:has(.blockui)`); it is hidden
  when the decision is minimised to the dock (19rem), where the list remains.
- **Ports**: the brief names 3041/3042 for probes; the four UI subagents each ran their own isolated
  build and server on 3044–3047 during development. Committed probes default to 3041 and refuse 3040.
- **PromptPanel's two pass-until buttons are still there** (it is hosted unmodified); the panel shows
  a run they started and offers Off.

## Found, not ours to fix (files this task may not touch)

- **`lib/BlockerPicker.svelte`, every surface**: choosing an attacker leaves the `<select>` blank
  (`<option value={attacker.id}>` is a number against a string `value`; Svelte 5 matches strictly).
  The assignment itself is right. One-line fix: `value={String(attacker.id)}`. `BlockUi` works around
  it (remembers each select's value at `change`, restores it, cross-checks the confirm label's count).
- **`hover.js` (C1)**: the hover overlay hides itself when its image fails, so under a Scryfall 429
  the two C1 hover checks go BAD (seen by two subagents; passed in the worker's and the reviewer's runs).
- **Redeal with a picker open** (`PromptPanel`): dealing from the menu while a discard picker is open
  leaves the old candidates up until Back. Not checked against C1.
- **Hand row width** (C1): past ~17 cards at 2560 the hand grew wider than its column and never
  paged; `.v3 .hand { min-width: 0 }` in `v3-order.css` fixes it.
