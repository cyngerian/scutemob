## Card-image store (`tools/play-server/src/images.rs`; owner ruling 2026-10-12)

- Layout `<store>/<small|normal|large>/<slug>.jpg`; slug = lowercased name, non-`[a-z0-9]` runs → `-`
  (≤60 chars), `-`, 16-hex FNV-1a-64 of the exact name. Written as `.part` then renamed.
- `GET /api/card-image?name=&version=` → 200 `image/jpeg` (30-day cache) | 404 `image_not_in_store`
  (`no-store`) | 400 `bad_params`. **Never fetches.** `GET /api/card-image/status` →
  `{enabled, store, queued, fetched, present, failed}` (failed names only — queued names would leak
  bot decklists). Neither route reads the session.
- Prefetch: `post_game` → after `session::new_game`, distinct commander + deck names go to a
  background thread (no session lock). Per card: 120 ms pause, one `api.scryfall.com/cards/named`
  call, one CDN download per missing size; 429 / 5xx retried ≤5 with 2/4/8/16 s backoff; non-JPEG and
  non-`cards.scryfall.io` URLs refused. `AppState::new` (every test) builds a serve-only service; only
  `async_main` installs a fetching one; all fetch logic is tested against a scripted `Net` fake.
- CLI: `--image-store <dir>` / `$SCUTEMOB_IMAGE_STORE` (default `tools/play-server/images`,
  gitignored), `--no-image-prefetch`, `--prefetch-images <decklist | names>` (`;` separates names when
  one contains a comma). `Cargo.lock` delta: one line (`ureq` in play-server's dependency list).
- Frontend: `cardImageUrl(name, version)` (`lib/v2/images.js`, additive) is the only image URL under
  `lib/v3` (table `small`, hover `normal`, card window `large`). `hover.js` and `CardWindow` now show
  a chip (name, type line, P/T from the hovered face) on a miss instead of hiding (the C2 "Found").
- Measured fill (seeds 0 + 3, real Scryfall): 1,254 s to `queued 0`; 6 names failed on 429 and were
  recovered by `--prefetch-images`; 384 cards × 3 sizes = 98 MB. `Poisonous Viper` and
  `Steel Guardian` are synthetic test cards (no printing) and are always chips.
